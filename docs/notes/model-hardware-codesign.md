# 模型—硬件协同设计

## 核心问题

模型应如何提出可量化的硬件需求，硬件限制又应在什么条件下反过来改变模型结构、数值表示或训练方法？本章处理的是跨层契约，而不是单向“让硬件跑模型”。

## 非目标

- 不把所有编译和 kernel 调优都称为协同设计。
- 不在缺少质量验证时仅凭吞吐宣称模型改进。
- 不直接给出芯片产品定义、成本或制造方案。
- 不假设模型、软件和硬件必须同时重做；优先选择能解除主要约束的最小跨层变化。

## 四层可调旋钮

| 层级 | 典型旋钮 | 必须记录的代价 |
| --- | --- | --- |
| 模型结构 | 维度、层数、attention 形式、专家数、路由 | 质量、训练稳定性、泛化能力 |
| 算法与数值 | 量化、缩放、稀疏、近似、重计算 | 误差、校准或再训练成本 |
| 编译与运行时 | 融合、分块、layout、调度、分片 | 适用 shape、复杂度、可移植性 |
| 硬件与系统 | 数据类型、存储层级、互连、阵列形状、指令支持 | 面积、功耗、带宽、利用率与通用性 |

协同设计的关键是指出哪一个约束无法被较低成本的软件映射充分消化，以及改变跨层契约为何更划算。

## 决策流程

1. **固定任务目标**：明确质量、吞吐、延迟、容量、能耗或成本约束。
2. **建立普通基线**：先用现有模型、软件栈和硬件完成映射与测量。
3. **识别硬约束**：区分暂时实现问题与长期资源上限。
4. **穷举局部选项**：评估不改变跨层契约的软件优化是否足够。
5. **提出协同候选**：说明模型侧和硬件侧分别改变什么。
6. **量化双向影响**：预测计算、搬运、容量、通信、质量和通用性变化。
7. **联合验证**：用系统指标和模型质量共同决定是否接受。

## 约束—响应矩阵

| 观测约束 | 模型或算法响应 | 软件或硬件响应 | 必查风险 |
| --- | --- | --- | --- |
| KV cache 容量或带宽过高 | MQA/GQA、KV 量化、窗口化 | 分页管理、低精度存储、带宽配置 | 长上下文质量、转换开销 |
| Attention 中间流量过大 | 调整 attention 形式 | 融合式 attention、片上驻留 | tile 边界、片上容量 |
| 矩阵维度难以填满阵列 | 调整 hidden/head/expert 维度 | 灵活 tile、尾部处理、不同阵列形状 | 参数量与模型质量 |
| MoE 通信与负载不均 | 路由约束、专家粒度、容量因子 | 专家放置、拓扑感知 collective | 丢 token、热点与尾延迟 |
| 低精度误差不可接受 | QAT、缩放策略、敏感层保留 | 累加精度、转换与校准支持 | 溢出、漂移、训练成本 |
| 非结构稀疏难以兑现 | 结构化稀疏或稀疏训练 | 稀疏指令、元数据路径、调度支持 | 元数据开销、有效稀疏率 |

## 协同设计记录模板

| 字段 | 要求 |
| --- | --- |
| 任务与约束 | workload、质量门槛、SLO、功耗或容量预算 |
| 基线映射 | 当前模型如何通过软件栈运行在目标硬件上 |
| 主导证据 | 性能模型、profile、容量或通信测量 |
| 已评估局部方案 | 哪些普通软件优化不足，原因是什么 |
| 跨层变化 | 模型、数值、编译、运行时、硬件各改变什么 |
| 资源预测 | operations、bytes、容量、通信、利用率变化 |
| 质量验证 | 数据集、指标、训练或校准条件 |
| 系统验证 | 延迟、吞吐、尾延迟、能耗、成本或扩展性 |
| 失败边界 | shape、规模、任务或架构变化后何时失效 |

## 三类共通过例

### Attention 与 KV

把上下文长度、batch、head 数、head dimension 和 KV 精度转成容量与带宽需求，再比较 GQA/MQA、量化、分页和片上存储能力。目标不是默认选择某一种 attention，而是确定资源拐点与质量代价。

### MoE 与系统拓扑

将专家数量、路由分布和容量因子转成设备负载与通信图。模型侧的路由约束必须与专家放置、互连拓扑和调度策略联合验证。

### 数值与稀疏

先确认目标硬件真正支持的计算、累加和稀疏模式，再决定训练、校准或结构约束。名义 dtype 或稀疏率不能自动转化为端到端收益。

## 与普通软件优化的边界

如果改变只涉及同一语义下的 fusion、tiling、layout、调度或 kernel 选择，优先归入[跨架构软件优化方法](./software-optimization-methodology.md)。只有当模型语义、训练约束、数值契约或硬件能力之一需要联动改变时，才进入协同设计记录。

## 完成标准

一项协同设计结论必须同时拥有普通基线、硬约束证据、局部方案排除过程、跨层资源预测、模型质量结果和系统实测；只给其中一侧收益不构成完整结论。
