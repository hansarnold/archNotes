# Cross-Architecture Software Optimization

## 核心问题

在不破坏语义、精度与服务目标的前提下，怎样系统地减少无效计算、数据搬运、同步等待和资源空闲？本章提供跨架构可复用的方法，而不是技巧清单。

## 非目标

- 不按厂商罗列 API、环境变量和局部调参技巧。
- 不在没有基线与瓶颈证据时直接给出优化方案。
- 不用单个 kernel 的峰值替代端到端收益。
- 不把模型结构或硬件契约的重大变化伪装成普通软件优化；这类问题归入[模型—硬件协同设计](./model-hardware-codesign.md)。

## 固定优化循环

1. **建立基线**：固定 workload、输入分布、精度、硬件、软件版本和端到端指标。
2. **分类瓶颈**：判断主要受计算、带宽、容量、延迟、通信、同步还是负载不均限制。
3. **定位责任层**：选择模型图、编译、kernel、运行时或分布式执行中的最小改动层。
4. **形成预测**：先写出预计减少的 operations、bytes、同步次数或关键路径时间。
5. **单变量实施**：一次只改变一个主要机制，保留可回退对照。
6. **联合验证**：同时检查局部指标、端到端指标、资源副作用和精度或质量。
7. **沉淀边界**：记录生效条件、失败条件与架构依赖，避免把特例推广成定律。

## 瓶颈到策略的映射

| 主要瓶颈 | 优先检查 | 候选策略 | 常见副作用 |
| --- | --- | --- | --- |
| 计算吞吐 | 算子数量、利用率、指令混合 | 算法简化、低精度、向量化、专用 kernel | 精度下降、转换成本 |
| 内存带宽 | bytes、复用距离、事务效率 | 融合、tiling、layout、压缩、预取 | 容量压力、复杂边界 |
| 存储容量 | 参数、激活、KV、临时 buffer | 重计算、量化、分页、分片、生命周期复用 | 额外计算或通信 |
| 启动与短任务延迟 | kernel 数、提交间隔、批大小 | 融合、图捕获、持久 kernel、批处理 | 灵活性降低、尾延迟变化 |
| 通信 | collective bytes、拓扑、重叠度 | 合理分片、压缩、通信计算重叠 | 负载不均、数值影响 |
| 同步与依赖 | barrier、事件、串行关键路径 | 缩小同步域、流水化、异步队列 | 正确性与调试难度 |
| 负载不均 | tile 尾部、专家路由、设备差异 | 重分块、动态调度、容量控制 | 调度开销与不可预测性 |

## 优化手段目录

### 改变工作量

消除冗余算子、常量折叠、剪枝、稀疏化和近似算法，直接改变需要完成的工作。必须同步记录语义或质量边界。

### 改变数据移动

通过融合、tiling、缓存、layout 与数据压缩提高复用或改善事务效率。这里要区分“逻辑 tensor 大小”和“真实经过存储层级的 bytes”。

### 改变执行顺序

用双缓冲、预取、流水和通信计算重叠缩短关键路径。总工作量可能不变，但等待时间和并发关系发生变化。

### 改变并行映射

调整 batch、tile、线程、设备分片、专家放置与 collective 方式。收益取决于 shape、拓扑和负载分布，而不只是并行度数量。

### 改变数值表示

使用低精度、混合精度、量化和缩放策略降低计算或搬运成本。任何收益都必须与累积误差、溢出风险和模型质量共同评估。

## 优化记录模板

| 字段 | 内容 |
| --- | --- |
| 基线 | workload、硬件、软件、精度、端到端指标 |
| 不变量 | 必须保持的语义、质量、SLO 与资源约束 |
| 瓶颈证据 | profile、counter、模型估计与关键路径 |
| 改动 | 改变了哪一层的哪个机制 |
| 资源预测 | operations、bytes、容量、同步或通信如何变化 |
| 实测 | 局部与端到端结果，包含方差和测量范围 |
| 副作用 | 编译时间、内存、尾延迟、精度、可移植性 |
| 适用边界 | 哪些 shape、batch、架构和版本下成立 |

## Transformer 共通过例

对一个 Transformer block，可按以下顺序建立候选集：

1. 先识别 GEMM、attention reduction、归一化、逐元素和 KV 状态的资源特征。
2. 用性能模型确认 prefill 与 decode 的主瓶颈是否不同。
3. 分别评估算子融合、KV layout、低精度、批处理与设备分片。
4. 对每项优化写出预期减少的 bytes、启动次数或关键路径时间。
5. 最后用端到端 TTFT、ITL、吞吐、容量和质量共同验收。

具体架构案例可从[推理软件优化](./software-optimization.md)继续阅读，但案例结论应重新填入本章模板后再复用。
